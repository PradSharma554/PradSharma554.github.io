CloudAIr

The access layer between websites and AI agents

A site owner registers their domain, proves ownership via DNS TXT or a well-known file, and CloudAIr becomes the interface AI agents use to read the site.

  • Crawler: robots.txt-compliant BFS with per-page Postgres checkpoints — crawls survive free-tier instance spin-downs and resume from the exact page where they died.
  • llms.txt generation: Gemini writes per-page summaries and section structure, throttled to free-tier quota, cached by content hash, with a deterministic non-LLM fallback so generation never fails.
  • MCP endpoint per site: stateless Streamable HTTP servers (official TypeScript SDK) exposing search_site, get_page and list_pages over Postgres full-text search.
  • Agent identification: ~30 known AI crawlers (GPTBot, ClaudeBot, PerplexityBot…) recognized from a maintainable signature table; MCP clients identified from their handshake.
  • Rate limiting: hand-rolled token buckets per (site, agent) with owner-configurable rules and correct Retry-After semantics.
  • Analytics: non-blocking buffered event pipeline, batch inserts, daily rollups with 30-day raw retention.
  • x402 paywall stub: HTTP 402 responses in the emerging agent-micropayments format, ready for a real facilitator.

Stack: TypeScript, Express, Next.js 15, Auth.js, PostgreSQL (Neon), Gemini, deployed on Render + Vercel free tiers with GitHub Actions as the cron layer. Total infrastructure cost: $0.
